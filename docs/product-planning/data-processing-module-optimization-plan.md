## 二、新增内容：3.4.1 数据处理机制选型

### 方案1：端到端视觉语言模型（VLM）

现代多模态大模型（GPT-4o、Gemini 2.5 Pro、Qwen-VL）可以直接输入报告图片，输出结构化 JSON，一阶段完成从原始文件到解析结果数据的转换。

**实现方式**：
- 将预处理后的文档页面直接送入 VLM
- 通过 prompt 指定输出 schema 和字段要求
- 模型一次性完成分类、版面理解、内容提取、实体识别和结构化输出

**优势**：开发复杂度低、准确率与管线方案相当或略高、单一模型调用减少编排负担。

**劣势**：中间过程不可见（黑盒），单字段错误无法定位到具体环节；溯源只能到原始输入，无法保留中间产物；规则干预仅靠 prompt 引导，无法插入确定性规则；单字段错误需全文重新推理，无法按阶段复用结果。

### 方案2：多阶段处理管线

将非结构化数据的处理过程拆解为六个独立阶段，各阶段顺序执行、输出独立留存、可独立调试和升级。

**实现方式**：详见 3.4.2。

**优势**：每阶段可独立调试和定位错误；每阶段输出可独立审计，溯源链完整；可在任意阶段插入确定性规则；错误修正只需重跑失败阶段。

**劣势**：多模块编排复杂度较高；多模型串行调用增加 GPU 时数；需要状态管理和阶段间契约设计。

### 方案对比

| 维度 | 方案1：端到端VLM | 方案2：多阶段管线 |
|------|-----------------|-------------------|
| 实现路径 | 多模态大模型直接输入报告图片，输出结构化JSON | 六阶段顺序处理（预处理→分类→版面→抽取→识别→输出） |
| 可解释性 | 黑盒，单字段错误难以定位根因 | 每阶段独立调试，错误可追溯到具体阶段 |
| 可追溯性 | 中间过程不可见，溯源只能到原始输入 | 每阶段输出独立留存，溯源链完整可审计 |
| 规则干预 | 仅靠 prompt 引导，规则可控性弱 | 每阶段可插入确定性规则，与匹配优先级链自然衔接 |
| 错误修正 | 单字段错误需全文重新推理 | 只重跑失败阶段，上游结果复用 |
| 开发复杂度 | 低（单一模型调用） | 较高（多模块编排、状态管理） |
| 运行成本 | Token 按量计费，长文档成本高 | 多模型串行 GPU 时数，可选择性调用 |
| 与建设原则的契合度 | 与"AI结果必须有依据""原始资料必须保存"存在张力 | 完全匹配五项建设原则 |

**选型说明**：方案1和方案2各有利弊。方案2在可解释性、可追溯性和规则可控性上更契合本文案的建设原则，当前展开详细设计以方案2为主，但方案1可作为后续技术演进方向——例如在管线后阶段（Stage 5-6）引入 VLM 替代传统 NER + 结构化输出，兼顾溯源能力和提取准确率。

## 三、管线程优化（3.4.2.1）

基于评估报告的四个缺失项和结构性问题，对管线程做以下修改：

| 阶段 | 改动点 | 改动内容 | 来源 |
|------|--------|---------|------|
| Stage 4 | 处理内容列 | 增加 OCR 语义校正："数字 PDF 直接文本提取，扫描件/拍照件走 OCR；OCR 结果经语义校正（利用上下文和医学术语先验修正识别错误）" | 评估报告 P2: OCR 后校正 |
| Stage 5 | 处理内容列 | 增加语境检测："医学实体抽取（项目名、结果值、单位、参考范围、结论、诊断、用药），实体关联标准项候选，实体语境检测（否定/情态/时序）" | 评估报告 P0: 否定与情态检测 |
| Stage 5 | 处理内容列 | "标准化"→"关联标准项候选"，与 3.4.3 标准匹配做命名区分 | 评估报告 P1: 边界区分 |
| Stage 5 | 关键约束列 | 增加"语境判断错误会导致语义反转（如'否认高血压'误判为高血压）" | 评估报告 P0 配套 |
| Stage 6 | 处理内容列 | 增加原文回验："按字段模板组装 JSON，逐字段标注置信度和来源依据；原文回验：校验提取值与原始文本一致性" | 评估报告 P1: 防幻觉 |
| Stage 6 | "schema"→"字段模板" | 提升非技术读者可读性 | 可读性优化 |
| Stage 6 | 关键约束列 | 增加"回验不通过标记待复核，不进入自动落表" | 评估报告 P1 配套 |

### 优化后的管线程

| 阶段 | 输入 | 处理内容 | 输出 | 关键约束 |
|------|------|---------|------|---------|
| 1. 格式预处理 | 原始文件（PDF/图片/扫描件） | 格式归一化、图片增强、编码转换 | 标准化文档页面 | — |
| 2. 文档分类 | 标准化文档页面 | 识别报告类型（检验/检查/出院小结/处方/体检），确定抽取字段模板 | 文档类型 + 字段集合定义 | 分类错误会传导至下游抽取字段错误 |
| 3. 版面分析 | 已分类文档 | 检测文本块、表格区域、阅读顺序，识别跨页表格延续 | 版面结构（区域坐标、阅读顺序） | 跨页表格的识别是结构还原的关键难点 |
| 4. 内容抽取 | 版面结构 + 原始页面 | 数字 PDF 直接文本提取，扫描件/拍照件走 OCR；OCR 结果经语义校正（利用上下文和医学术语先验修正识别错误） | 结构化文本块（含位置信息） | 数字 PDF 和扫描件走不同提取路径；OCR 校正不能改变原文语义 |
| 5. 实体识别与关联 | 结构化文本块 | 医学实体抽取（项目名、结果值、单位、参考范围、结论、诊断、用药），实体关联标准项候选，实体语境检测（否定/情态/时序） | 实体列表（含标准项候选、语境标记） | 依赖标准数据体系的完整性和同义词覆盖；语境判断错误会导致语义反转（如将"否认高血压"误判为高血压） |
| 6. 结构化输出与校验 | 实体列表 | 按字段模板组装 JSON，逐字段标注置信度和来源依据；原文回验校验提取值与原始文本一致性 | **解析结果数据** | 置信度评分决定后续路由策略；回验不通过标记待复核，不进入自动落表 |

### 管线设计原则补充

在原有原则"每阶段的失败模式可被下游检测、补偿或路由"基础上，增加：

> 管线不仅负责"提取"，也负责"验证"——Stage 5 的语境检测和 Stage 6 的原文回验构成双重安全网：语境检测防止语义反转（假阳性），原文回验防止无中生有（幻觉）。两项验证的失败均路由到人工复核，不进入自动落表。

## 四、3.4.3 标准匹配补充说明

在 3.4.3"标准匹配与标准化"章节开头增加一句与管线的衔接说明：

> 管线 Stage 5 已将实体关联到标准项候选，本章的标准匹配在此基础上按匹配优先级链做精确判定。管线内关联给出的是候选（粗匹配），标准匹配给出的是确定结论（精匹配）。两者分离的好处是：匹配规则升级后，可基于同一批候选结果重新执行本章的匹配逻辑，不需要重跑整条管线。
