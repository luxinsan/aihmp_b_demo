# 健康管理方案体系脑暴

## 1. 文档定位

本文是健康管理方案体系重构前的业务脑暴文档。当前阶段抛开既有系统、既有页面和历史实现，只从慢病管理与长期健康管理业务本身出发，建立基础业务理解并形成阶段性结论。

本文不讨论页面设计、技术实现、接口字段和当前代码改造。本文重点回答：

- 慢病 / 健康管理业务的本质是什么。
- 真实业务中一般如何进行持续健康管理。
- 业务中有哪些稳定角色、对象、动作、数据和闭环。
- 后续设计健康管理方案体系时，应以什么业务原点作为判断依据。

## 2. 业务本质

慢病 / 健康管理不是一次性诊疗，也不是单次报告交付，而是一套围绕特定人群持续运行的服务管理过程。

它的核心是：

```text
识别需要管理的人
-> 判断当前健康状态和风险
-> 设定阶段性管理目标
-> 安排患者和医护要执行的动作
-> 持续采集数据和反馈
-> 发现异常并干预
-> 周期性评估效果
-> 决定继续、调整、升级干预或结束
```

因此，慢病 / 健康管理本质上是长期服务闭环，不是内容生成，不是任务下发，也不是单纯健康档案展示。

## 3. 典型业务主线

慢病 / 健康管理的通用主线可以抽象为：

```text
筛查 / 发现
-> 建档 / 纳入管理
-> 风险分层
-> 基线评估
-> 制定管理目标
-> 制定管理方案
-> 执行管理任务
-> 数据监测与反馈
-> 异常识别与干预
-> 阶段评估
-> 方案调整 / 续管 / 结营 / 转诊
```

这条主线基本适用于高血压、糖尿病、体重管理、血脂管理、术后康复等长期管理场景。

业务理解上，应先围绕这条主线确认对象和规则，再讨论功能模块和页面形态。

## 4. 核心参与角色

慢病 / 健康管理不是单角色业务，至少涉及以下几类角色：

| 角色 | 业务职责 |
| --- | --- |
| 患者 / 居民 / 服务对象 | 接收计划、执行任务、打卡、上传数据、反馈症状、查看建议 |
| 医生 | 判断疾病和风险，确认目标，处理关键异常，决定转诊或治疗调整 |
| 护士 / 健康管理师 | 建档、随访、提醒、任务跟进、生活方式指导、执行过程管理 |
| 机构 / 科室管理者 | 管理服务人群、查看管理质量、分配团队、监督执行效果 |
| 系统 / AI | 辅助识别数据、生成摘要、推荐方案、提醒异常、归档记录，但不替代专业确认 |

方向性判断：

- 高频运行链路通常是患者与护士 / 健康管理师之间的日常服务链路。
- 医生更多参与关键判断、异常处理、方案确认、转诊和治疗调整。
- 系统和 AI 的价值在于辅助整理、提示、推荐和归档，不应替代专业决策。

## 5. 核心业务对象

从业务本身看，稳定对象大致包括：

```text
患者
健康档案
管理主题
管理方案
管理目标
监测数据
健康任务
打卡记录
随访记录
预警事件
干预记录
阶段评估
健康报告 / 方案文档
```

这些对象之间的初步关系可以表达为：

```text
患者
-> 有健康档案
-> 被纳入某个管理主题
-> 形成一份管理方案
-> 方案拆解为目标、任务、监测、打卡、预警和评估
-> 执行过程产生数据、记录和事件
-> 阶段评估汇总结果
-> 形成下一步管理决策
```

当前阶段的关键判断：

- 后续产品设计不应从页面出发，而应先从这些业务对象及其关系出发。
- 健康管理业务的复杂度主要来自对象之间的关系，而不是单个页面的字段数量。

## 6. 健康管理方案的业务定位

健康管理方案不应被理解为一份静态文档。

它更像是一个服务执行框架，负责回答：

```text
管谁？
为什么管？
当前状态如何？
这一阶段要达成什么？
患者要做什么？
医护要做什么？
系统要监测什么？
异常时怎么处理？
阶段结束如何评估？
下一步如何调整？
```

因此，一份完整健康管理方案至少应包含：

```text
管理主题
适用对象
基线评估
管理目标
监测数据
患者任务
医护任务
打卡 / 反馈机制
预警规则
随访安排
阶段评估
调整规则
```

阶段性结论：

- 健康管理方案的核心不是展示建议，而是组织服务执行。
- 方案必须连接目标、执行、数据、异常和评估，否则无法构成长期管理闭环。

## 7. 典型执行动作

### 7.1 患者侧动作

患者侧常见动作包括：

```text
测量血压 / 血糖 / 体重
记录饮食、运动、睡眠、用药
完成问卷或量表
阅读宣教内容
执行复查或门诊复诊
反馈症状或不适
查看阶段建议
```

患者侧关注重点是：接收、理解、执行、反馈和查看结果。

### 7.2 医护侧动作

医护侧常见动作包括：

```text
建档
评估风险
制定或确认方案
下发任务
查看监测趋势
查看患者打卡和依从性
随访
处理异常
调整目标或任务
生成阶段总结
判断是否转诊或结营
```

医护侧关注重点是：判断、配置、跟进、干预、调整和评估。

### 7.3 系统侧动作

系统侧常见动作包括：

```text
同步健康数据
整理指标趋势
提醒患者执行任务
提醒医护跟进异常
识别未打卡、超阈值、任务逾期
生成摘要或评估建议
归档服务过程
```

系统侧关注重点是：数据汇聚、规则识别、提醒触达、辅助生成和过程归档。

## 8. 业务闭环的关键

慢病管理不能只下发任务。

真正有价值的问题是：

```text
任务是否执行？
执行后产生什么数据？
数据是否达标？
患者是否持续参与？
是否出现异常？
医护是否处理？
处理后是否改善？
下一阶段是否需要调整？
```

因此，任务下发只是起点，执行反馈、数据变化、医护干预和阶段评估共同构成闭环。

阶段性结论：

- 如果没有反馈和评估，健康管理只能证明“发过任务”。
- 如果有数据、异常处理和阶段评估，健康管理才能证明“持续管理产生了结果”。

## 9. 慢病管理中的数据类型

业务中会反复使用以下数据：

| 数据类型 | 示例 | 主要用途 |
| --- | --- | --- |
| 基础档案 | 年龄、性别、身高、体重、病史 | 判断适用对象和基础风险 |
| 指标数据 | 血压、血糖、HbA1c、LDL-C、BMI、腰围 | 目标设定、趋势监测、预警和评估 |
| 行为数据 | 饮食、运动、睡眠、用药、饮水 | 判断依从性和生活方式改善 |
| 症状数据 | 头晕、胸闷、乏力、低血糖症状 | 异常识别和医护跟进 |
| 过程数据 | 问卷、随访、任务完成、复查结果 | 判断服务是否闭环 |
| 评估数据 | 目标达成率、风险变化、依从性评分 | 阶段复盘和管理质量评价 |

需要特别区分：

```text
监测数据 = 被持续观察的结果
打卡 = 患者形成记录的动作入口
任务 = 要完成的服务动作
预警 = 对异常状态的识别和处理入口
评估 = 对一段管理周期的复盘
```

这几个对象不能混成同一个概念。

## 10. 典型异常场景

慢病管理必须处理异常，否则只是健康打卡工具。

常见异常包括：

```text
血压 / 血糖 / 体重等指标超过阈值
连续未打卡
任务逾期未完成
患者反馈不适症状
用药依从性差
复查未完成
指标长期不改善
短期趋势快速恶化
患者失联
```

异常之后不能只做提示，而应连接处理动作：

```text
提醒患者
通知医护
生成随访任务
要求复测
建议复诊
升级给医生
调整方案
记录处理结果
纳入阶段评估
```

阶段性结论：

- 预警不是页面提醒，而是异常处理流程的入口。
- 预警必须能连接医护干预、患者动作和处理记录。

## 11. 阶段评估的业务价值

阶段评估是慢病管理从执行走向管理的关键。

它回答：

```text
这一阶段有没有效果？
目标是否达成？
指标有没有改善？
患者有没有按要求执行？
发生过哪些异常？
医护是否及时处理？
下一阶段继续原方案，还是调整？
是否需要结营、转诊或升级干预？
```

没有阶段评估，系统只能证明发过任务；有阶段评估，系统才能证明管理产生了结果。

阶段评估的输入通常包括：

- 目标达成情况。
- 指标趋势。
- 打卡完成情况。
- 任务完成情况。
- 随访完成情况。
- 预警发生与处理情况。
- 患者反馈。
- 医护评价。

阶段评估的输出通常包括：

- 阶段总结。
- 管理效果判断。
- 调整建议。
- 下一阶段计划。
- 结营、续管、转诊或升级干预判断。

## 12. 行业标杆的共同启发

无论是国内基层高血压 / 糖尿病管理，还是国际糖尿病预防项目、远程慢病管理平台，行业标杆共同强调的不是复杂页面，而是以下稳定能力：

```text
人群识别
风险分层
结构化目标
持续监测
患者自我管理
健康管理师 / 医护跟进
异常干预
阶段复盘
长期效果追踪
```

行业实践给出的共同启发是：

> 把健康管理变成一套可执行、可监测、可干预、可评估的长期服务流程。

## 13. 当前阶段业务结论

基于初步调研，当前阶段先形成以下业务结论：

1. 慢病 / 健康管理的核心对象是“患者在某个健康管理主题下的一段持续管理过程”。

2. 健康管理方案不是静态文档，而是承载目标、任务、监测、打卡、预警和评估的执行框架。

3. 健康管理必须区分模板和患者实例：模板负责标准化，实例负责个体化执行。

4. 数据不是附属展示，而是管理过程的判断依据，包括基线、监测、预警和评估。

5. 打卡不是任务本身，而是患者侧记录、反馈和参与的入口。

6. 任务不是闭环本身，任务完成后的数据变化、异常处理和阶段评估才构成闭环。

7. 预警必须连接处理动作，否则只是风险提示。

8. 阶段评估是判断管理是否有效、是否调整方案的关键节点。

9. 医护端关注管理和干预，患者端关注执行和反馈。

10. AI 可以参与摘要、推荐、生成和解释，但关键医学判断必须保留人工确认。

## 14. 一句话定义

慢病 / 健康管理业务可以先被定义为：

```text
围绕特定健康问题，对患者进行建档、分层、目标设定、方案执行、数据监测、异常干预和阶段评估的持续服务闭环。
```

这一定义是后续健康管理方案体系、对象建模和页面设计的业务原点。
